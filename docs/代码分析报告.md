## 1. 项目概览

## 6. 关键模块解析

### 6.1 Electron 主进程：`electron/main.ts`

- **主窗口**：无边框自定义标题栏；通过 `session.defaultSession.setDisplayMediaRequestHandler` 接管 `getDisplayMedia`，配合 `desktopCapturer` 实现“源选择器”与“自动复用上次选择的源”（为设备切换后的自动重捕获打基础）。
- **字幕窗口**：透明/置顶/鼠标穿透，独立页面加载 `caption.html`；通过 IPC 接收文本与样式更新；通过定时器检测鼠标命中区域来切换交互模式（用于显示锁/设置按钮）。
- **托盘与快捷键**：Tray 菜单 + 全局快捷键（`CommandOrControl+Shift+D`，失败后尝试备用快捷键）。
- **自动更新**：由渲染进程通过 IPC 触发检查/下载/安装；主进程转发更新状态与下载进度；下载完成后弹窗提示“立即安装/稍后”。
- **火山代理（内置）**：主进程内置 `3001/ws/volc` 的 WebSocket 代理，用 Node 的 `ws` 建连火山并设置所需 Headers，再把结果转发给渲染进程侧的 WebSocket。

### 6.2 Preload：`electron/preload.ts`

- 通过 `contextBridge.exposeInMainWorld('electronAPI', ...)` 暴露安全 API：窗口控制、源列表/选择、自动更新事件、字幕控制与状态事件等。
- 多数事件订阅会返回 cleanup 函数；部分实现使用 `removeAllListeners`（需要关注“多订阅场景”下的潜在互相干扰）。

### 6.3 前端入口与页面拆分

- 主页面入口：`frontend/src/main.tsx` → `frontend/src/App.tsx`
- 字幕页面入口：`frontend/src/caption-main.tsx` → `frontend/src/components/CaptionOverlay.tsx`
- Vite 多入口：`frontend/vite.config.ts` 将 `index.html` 与 `caption.html` 同时打包，供 Electron 两个窗口分别加载。

### 6.4 录制与转录主流程：`frontend/src/hooks/useASR.ts`

抽象数据链路：

1. 选择 ASR Provider（store 中 `settings.currentVendor`）
2. `getDisplayMedia` 获取系统音频（Electron 环境由主进程提供更稳定的源选择/复用）
3. 连接 Provider（Soniox 直连 WebSocket；火山通过本地 proxy）
4. 采集音频并推流：
   - Soniox：MediaRecorder 生成 WebM/Opus chunk（100ms）
   - 火山：WebAudio → PCM16@16k → 推给 proxy
5. Provider 产出 tokens/partial/final → Zustand store → UI 与字幕窗口（IPC）

设备切换处理：

- 监听 `navigator.mediaDevices.devicechange`，做节流（10 秒内不重复重启）并自动重捕获；对非火山提供商会重连 provider。

### 6.5 Provider 抽象层：`frontend/src/providers/*`

- `BaseASRProvider`：状态机 + 事件回调（`onPartial`/`onFinal`/`onTokens`/`onError`…）。
- `ProviderRegistry`：注册并创建 Provider 实例（目前内置 Soniox、Volc）。
- `SonioxProvider`：浏览器 WebSocket 直连；对 tokens 做归一化，并过滤特殊标记。
- `VolcProvider`：连接本地 proxy（`ws://localhost:3001/ws/volc`），通过 `ready/partial/final/error` 事件驱动 UI 更新。

### 6.6 数据持久化：`frontend/src/utils/storage.ts`

- sessions / settings / tags 全部使用 localStorage。
- 支持数据导出/导入（覆盖/合并）以便迁移。
- API Key 以明文形式保存在 localStorage（风险与改进建议见后文）。

## 7. 主要风险点与改进建议（按优先级）

### P0：凭证在 URL Query 中传递（Volc）

现状：

- `VolcProvider` 将 `appKey/accessKey` 作为查询参数拼在 WebSocket URL 上，代理端再解析。

风险：

- Query 参数容易被日志、调试输出、崩溃报告、代理层抓包等记录；即使是 `localhost`，仍不够“最小暴露面”。

可选改进方案：

- **方案 A（推荐）**：WebSocket 连接建立后，客户端第一帧发送 `config` JSON（含 `appKey/accessKey`），URL 不带敏感信息；代理端先等 `config` 再连火山。
  - 优点：敏感信息不出现在 URL；更易做权限校验与续期；便于未来支持 token 刷新。
  - 缺点：需要改动本地 proxy 协议（但两端都在本项目可控）。
- **方案 B**：仍用 URL，但将敏感字段改为短期 token（通过一次性握手生成）。
  - 优点：改动相对较小。
  - 缺点：仍保留 URL 泄露面，只是降低危害。

### P1：火山代理实现重复（`electron/main.ts` 与 `server/src/volcProxy.ts`）

现状：

- 两套实现逻辑高度相似，长期会产生漂移与 bug 不一致。

可选改进方案：

- **方案 A（推荐）**：抽出 `packages/volc-proxy`（纯 TS 模块），同时被 `electron` 与 `server` 复用；统一协议与单测。
- **方案 B**：明确只保留一种实现（如果最终产品只需要 Electron 内置 proxy，可考虑移除 `server` 代理相关代码）。

### P1：缺少自动化测试与契约验证

现状：未发现测试框架与用例。

建议优先级：

1. 先加“协议与工具类”单测（subtitle 导出、token 归一化、volc 帧编解码、storage 导入导出校验）。
2. 再补 E2E/集成（可选）：Playwright + Electron runner 跑关键流程（启动、配置、开始/停止录制、字幕窗口显示）。

### P2：ESLint 脚本可能不可用（缺少配置）

现状：`frontend` 有 `npm run lint`，但未发现 eslint 配置文件。

建议：

- 增加 `frontend/eslint.config.js`（Eslint 9 flat config）或调整版本/脚本，确保 lint 可在 CI 中稳定运行。

### P2：`AudioProcessor` 使用 `ScriptProcessorNode`（已废弃）

建议：

- **方案 A（推荐）**：迁移到 AudioWorklet（更低延迟、性能更好、未来兼容性更稳）。
- **方案 B**：保留现状但增加降级/告警，并确保输出静音（避免意外回放）。

### P2：API Key 存储安全

现状：localStorage 明文保存。

建议：

- Electron 环境可考虑使用 `safeStorage` 或系统钥匙串（Windows Credential Manager）存储敏感信息；渲染层仅拿到临时 token 或受限代理能力。

### P3：默认样式/类型的重复定义

现状：CaptionStyle 默认值在主进程、store、字幕渲染组件中均有一份，存在漂移风险。

建议：

- 集中到单一来源（例如 `frontend/src/constants/caption.ts`），并通过 IPC 同步（启动时以用户设置为准）。
